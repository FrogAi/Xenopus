# Specialist library and model presets

Read when current task evidence warrants a library or preset improvement. The coordinator entrypoint owns routine delegation, opportunity assessment and integration.

## Maintain the agent library

A first encounter or successful general-agent fallback can establish a method worth preserving; a specialist need not possess a capability absent from a general agent.

Inspect the catalog and evidence. Improve an existing coherent owner or create a focused profile when separate selection, instructions, context or a preset adds concrete reusable value. Preserve useful methods, verification standards and deliverables that would otherwise need reconstruction. Do not create duplicate or speculative roles or stretch one into a catch-all. Diagnose whether underperformance belongs to the assignment, profile, routing, discovery, tools, evidence or model settings before repairing it.

Consolidate or retire profiles for evidenced redundancy, harm, obsolescence or better ownership. Infrequent use, one unexplained miss or successful general fallback alone is insufficient. Preserve useful coverage, update routing and references, settle active owners and keep recoverable retired definitions outside discovery.

Standing authorization covers creating, improving, rewriting, consolidating and retiring user-owned profiles, revising their model/reasoning presets across families or tiers, and necessary coordinator routing or metadata repairs. Apply qualifying improvements during the task through the `improve-personal-customizations` skill, which owns admission boundaries, verification, installation, recovery and records. Preserve task checkpoints and authority. If that workflow or a required capability is unavailable, keep the change inactive and report its blocker. Do not repeat unchanged assessments or keep refining after completion.

## Maintain model presets

Treat presets and inherited defaults as revisable unless explicitly constrained. Evaluate changes when task evidence, underperformance or model changes establish an opportunity. Choose demonstrated role and integrated-result quality; prefer lighter settings when heavier ones provide no demonstrated useful benefit, without trading away correctness, completeness or reliability.

Verify candidate IDs, access and supported model/effort settings on the actual execution surface using current official documentation and runtime evidence. Consider candidates across versions, families and tiers. Never invent aliases or version strings, treat cached listings or public releases as proof of access, or mistake a pinned version for a deliberate freeze. In Claude Code, a profile's preset is the `model` and `effort` front matter of its agent file. The Agent tool's `model` parameter changes only the model, and only to short aliases, which may not resolve to the newest version of each family; where workflows are allowed, a workflow `agent()` call accepts full model IDs and sets both model and effort, so use it to compare exact settings. Honor explicit provider, model, effort, data and cost restrictions.

Compare promising candidates with the verified baseline on representative role checks, relevant failures and the integrated result. Verify the effective settings, including inheritance and overrides. Persist the best-supported choice through the maintenance workflow; retain useful inheritance when no override is warranted. If evidence is insufficient, retain the best verified option and report material blockers. Keep model choices in profiles, and avoid redundant benchmarking, repeated switching or a separate background optimization mechanism.
