# Visual fidelity verification

Compare the approved reference with the actual integrated implementation. Visual similarity and working behavior are separate requirements; neither substitutes for the other.

## Preserve and align the reference

Use the exact approved source/version and its captured states. When code is available, render that preserved reference in the same environment as the product. Never generate the expected image from the implementation being tested, update it to match a failure or recapture an edited reference without an authorized design change. Keep reference provenance and before/after artifacts outside the product repository and disposable build output.

Match the rendering conditions that can affect the comparison: browser/version and host environment, viewport width and height, device-pixel ratio, zoom, theme, locale, date and time zone, content, scroll position, interaction state and relevant user preferences. Compare the actual product viewport rather than a scaled review frame. Browser rendering can differ across environments; matching the capture environment is necessary for reliable comparisons. [Playwright's official visual-comparison guidance](https://playwright.dev/docs/test-snapshots) describes these limitations.

Ensure the required fonts and weights, images and other visible assets have loaded. Reach the intended state and establish a stable layout before capture; a blank lazy-loaded section or fallback font is not valid comparison evidence. Use deterministic fixtures for changing data, freeze time or motion consistently where needed, and inspect animation/transition behavior separately. Stabilize captures through supported testing capabilities without changing the shipped design to make a screenshot pass.

For an image-only reference, retain the supplied image and its known capture properties. Do not stretch it, guess its pixel ratio or resize the implementation to conceal a mismatch. Request missing information when it materially blocks fidelity. Mark unseen responsive layouts, offscreen content or interaction states as unspecified; do not claim those match a reference that does not depict them. When an image reference was rendered by a different tool, browser or encoder than the product, its text antialiasing and compression artifacts may be impossible to reproduce. Confirm that a remaining difference is only that, by overlay and by measured positions, sizes, sampled colors and type metrics; correct every other difference, and report that bound instead of a pixel-perfect claim.

## Compare, diagnose and repair

Take pixel-comparison captures as unscaled image files at a set viewport size and device-pixel ratio, for example with a short scratch script using an already installed Playwright. Diff them with no color threshold and with antialiased pixels counted, and keep the difference image for overlay inspection. A browser screenshot that may be scaled to fit is for inspection, not pixel evidence. Measure the rendered geometry and computed styles of matching reference and product elements to find why renders differ. Prefer existing tools and temporary checks over installing a new visual-testing framework. Obey the current browser/tool access rules; a documented capability in another runtime does not make it available here.

Inspect the whole affected page and important details at native scale. Compare element positions and sizes, text baselines and wrapping, exact fonts/weights, spacing, colors, borders, image crops and interactive affordances. Use difference images to locate discrepancies, then trace their cause in the actual product: inherited styles, default control appearance, layout constraints, asset choice, font loading or state/data mismatch. Fix the responsible code and repeat affected comparisons after integration.

Target zero implementation-caused pixel differences under matched, deterministic conditions. Do not treat a permissive default threshold or whole-page percentage as proof that every detail matches. Inspect diff settings and residual regions: a small missing icon, changed label or one-pixel shift can be hidden by an aggregate score. If a comparison tool suppresses antialiasing or other pixels, disclose that scope and inspect it separately where it could conceal a real design difference.

Do not declare a residual difference harmless from appearance alone. Establish rendering variability through repeated unchanged reference captures or other direct evidence, isolate it narrowly and report its effect on the claim. Correct reproducible implementation differences. Stabilize volatile content instead of masking it where possible; any necessary exclusion must be explicit, narrow and outside the visual detail being certified. Never exclude mismatched layout or content to pass. Unresolved differences remain unresolved even after substantial effort.

## Cover the accepted experience

Compare every approved desktop, tablet and mobile view and every specified browser/theme, plus meaningful breakpoints and intermediate/reduced-height layouts. Scope follows the reference and product contract; a single screenshot does not establish all-device parity. When only one reference view exists, verify that view exactly and ask the user about material missing responsive decisions rather than manufacturing broader approval.

Exercise the affected menu, tab, dialog, selected, hover/focus, disabled, loading, empty, validation, error and success states that exist in the agreed feature. Match their visual treatment where referenced and verify their real outcomes. Test keyboard use and relevant reduced motion, and check long/short production content without replacing the reference fixture used for comparison. A passing initial view does not certify an opened menu, a saved form or a different content length.

Rerun comparisons on the final integrated code after functional, shared-style or dependency changes that can affect appearance. When the change edits shared styles or components, also capture one page of each other kind that uses them before and after the change, and confirm it is unchanged or report each difference. Preserve one concise mapping of reference version, final revision, capture conditions, widths/states, observed differences and accepted exceptions. Give that evidence and the actual artifacts to the independent reviewer; the implementer's summary alone cannot establish fidelity.
